# Dependencies and licences

> **Applies to:** Developers

This article lists Lumen's npm dependencies with their licences, explains what the important ones are used for,
and points to the notices for bundled assets and ported code. Read it before you add a package or ship a build.

Lumen itself is released under the MIT licence (`LICENSE`). Power BI is a trademark of Microsoft; Lumen is an
independent project and is not affiliated with or endorsed by Microsoft.

## What the main dependencies do

| Area | Packages | Used in |
|---|---|---|
| Application shell | `electron`, `react`, `react-dom`, `zustand`, `immer` | the app, the stores (`src/renderer/src/state/`) |
| Build and test | `electron-vite`, `vite`, `@vitejs/plugin-react`, `typescript`, `vitest`, `playwright-core` (the end-to-end driver) | `npm run *`, `e2e/` |
| Packaging | `electron-builder` | `npm run dist` (see [Build and packaging](build-and-packaging.md)) |
| Editors | `codemirror`, `@codemirror/*`, `@lezer/highlight` | formula bar, DAX query view, M editor (`src/renderer/src/editors/`) |
| Grids | `@tanstack/react-virtual` | Table view, DAX query results, Power Query preview |
| Charts and maps | `d3`, `topojson-client`, `world-atlas`, `us-atlas` | visuals; offline map shapes |
| Custom visuals | `vega`, `vega-lite`, `vega-embed`, `dompurify` | Deneb visual; HTML Content sanitising (`visuals/custom/htmlSanitize.ts`) |
| Code visual | `sucrase` (JSX and TypeScript to JavaScript, a lazy chunk), `@codemirror/lang-html`, `@codemirror/lang-css`, `dompurify`, `react` (also bundled into the frame as `codeframe/react.js`) | `src/renderer/src/visuals/code/`, `src/renderer/codeframe/` ([Code visual internals](code-visual-internals.md)) |
| Icons and fonts | `@fluentui/react-icons`, `react-icons`, `@fontsource/open-sans` | UI icons, built-in icon sets ([ICONS.md](../ICONS.md)), fallback font |
| File formats | `fflate` (zip and deflate), `sql.js` (reads `metadata.sqlitedb` in a `.pbix`), `exceljs`, `hyparquet` | `src/core/io/`, `src/core/data/xlsx.ts`, `src/core/data/parquet.ts`, Get data readers |
| Export | `pptxgenjs`, `exceljs` | PowerPoint export, Excel export of visual data (`src/renderer/src/export/`) |
| Connectors (main process) | `tedious`, `@azure/identity`, `pg`, `mysql2`, `@duckdb/duckdb-wasm`, `@aws-sdk/client-s3`, `google-auth-library` | SQL Server and Fabric with Entra ID, PostgreSQL, MySQL, DuckDB, S3, Firestore (`src/main/ipc/connectors*`) |
| Other | `nanoid` (ids), `hyparquet-writer` (the `datasets/` generator only) | |

## Bundled assets and ported code

`THIRD_PARTY_NOTICES.md` at the repository root lists the third-party works that are copied into the repository
or ported to TypeScript, as opposed to installed from npm. Among them:

- the **Selawik** font (SIL Open Font License 1.1) in `src/renderer/src/assets/fonts/selawik/`, and the derived
  "Lumen Sans Semibold" face built by `scripts/fonts/make-semibold.py`, which stays under the OFL with another name;
- the **XPress9 / XPress8** decoders, ported from MIT-licensed Python implementations, and format knowledge from
  **pbixray** / **xmhuffman** (MIT), in `src/core/io/pbix/datamodel/` (details in `THIRD_PARTY.md` there);
- Microsoft's **CY24SU10** base theme JSON in `src/core/report/themes/`;
- icon artwork from **Lucide** (via `react-icons`) and **Fluent UI System Icons**, with licence texts in
  `resources/licenses/icons/`.

The DAX and M engines in `src/core/dax` and `src/core/m` were vendored from an earlier project (the code comments call
it "Parity"); `THIRD_PARTY_NOTICES.md` does not list them as third-party code.

When you add a font, an icon set, a data file or code ported from another project, add a row to
`THIRD_PARTY_NOTICES.md` with the component, its licence, where it lives and what was changed.

## Considerations and limitations

- Three runtime dependencies are not imported anywhere in `src/`: `@xyflow/react`, `@fontsource/barlow` and
  `@fontsource/roboto-condensed`. The font families "Barlow" and "Roboto Condensed" are named in the font stacks of
  `src/renderer/src/visuals/common/text.ts`, but the packages' CSS is never imported, so those faces are only used
  when they are installed on the system.
- Several `@types/*` packages are listed under `dependencies` rather than `devDependencies`. This has no effect on
  the app, which bundles the renderer.
- The licence column shows what each package declares; it is not legal advice.
