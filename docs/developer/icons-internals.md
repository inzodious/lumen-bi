# Icons internals

> **Applies to:** Developers

This article explains how Lumen's built-in icons are referenced, drawn, saved into PBIR so that Power BI is designed to show them as ordinary images (not verified), and kept in step with the report. The design document with the full storage format, verification status and bundle sizes is [ICONS.md](../ICONS.md); this article is the developer's map of the code and links there for detail.

## Overview

A creator can put an icon in an image visual, or in a new card's callout image or card image, from **Insert > Icon** or from the Format pane. The icons are the React components of two libraries:

| Set id | Components | Icons |
|---|---|---|
| `lucide` | `react-icons/lu` (react-icons 5.7.0) | 1,541 |
| `fluent-color` | the unsized `*Color` components of `@fluentui/react-icons` (2.0.346), re-exported by a generated barrel | 196 |

The counts are what `src/renderer/src/icons/registry.test.ts` prints for the installed packages. The curated **Business & dashboards** category holds 409 Lucide and 134 Fluent Color icons.

Lumen never assembles icon SVG from path data: the canvas, the picker and the Format pane render the components, and the picture saved for Power BI is the component's own server-rendered output.

| | `src/renderer/src/icons/picture.ts` | `renderIconPicture()`: the standalone SVG saved for Power BI (ids prefixed `lumen-`). |

| | `src/renderer/src/icons/IconPicker.tsx`, `IconSourceRows.tsx` | `openIconPicker()` and the Format pane rows. |

An `IconRef` is the editable reference:

```ts
export interface IconRef {
  set: IconSetId
  name: string          // kebab-case of the component name without its prefix / suffix
  color?: IconColor     // single-colour sets only
  strokeWidth?: number  // sets with strokes only
  padding?: number      // % of the icon box, 0 to 40
}
```

Theme colours use PBIR `ThemeDataColor` ids (0 background, 1 foreground, 2 and up the data colours), so an icon drawn in a theme colour follows a theme change.

## From the Format pane to the file

1. A visual definition declares an image slot that can hold an icon with a format property of type `iconSource` and a `FormatIconSlot` (see [The visual contract](visual-contract.md#format-cards-and-properties)). The image visual (`visuals/elements/index.ts`) and the card's `image` and `cardImage` objects (`visuals/cards/index.ts`) do.
2. `PropEditor.tsx` renders that row with `IconSourceRows`: for the image visual a **Source** choice between an image file and an icon; for cards an **Icon** entry added to the slot's own **Image source** dropdown (`typeProp: 'imageType'`).
3. Choosing an icon opens `openIconPicker()`, which resolves to an `IconRef`.
4. `setVisualIcon(pageName, visualName, slot, ref)` loads the set, renders the picture with `renderIconPicture(ref, theme)` and calls `bakeIcon()` inside one `mutateReport` edit, so it is one undo step.
5. `bakeIcon()` in `core/icons/bake.ts` stores the picture in the slot's form and records an `IconBinding` in the visual's `Lumen_Icon` annotation:

```ts
export interface IconBinding {
  slot: IconSlot
  icon: IconRef
  bake: string        // fingerprint of what was baked
  resource?: string   // form 'resource'
  restore?: Record<string, unknown> // form 'dataUri': the slot's source properties before the icon
}
```

The two storage forms:

- **`resource`** (image visual): an SVG registered resource `StaticResources/RegisteredResources/LumenIcon_<set>_<name>_<hash>.svg`, listed in `report.json` `resourcePackages`, referenced from `visual.objects.general[0].properties.imageUrl` as a `ResourcePackageItem`, the same way Power BI stores an uploaded image.
- **`dataUri`** (new card images): the SVG as a `data:image/svg+xml;base64,...` URI in the slot's `imageUrl`, with `imageType: 'imageUrl'`. The write goes to the entry the card reads, following the `{ id: 'default' }` rule in `core/report/entries.ts`; a data-bound source in that entry is removed and remembered in `restore`.

**Insert > Icon** (`insertIcon()` in `app/commands.ts`) creates an image visual and bakes the chosen icon into `IMAGE_VISUAL_SLOT` the same way.

## Keeping pictures current

- **Theme change**: `actions.ts` registers a follower with `onReportThemeChange()` (`state/store.ts`) that re-bakes every theme-coloured icon in the same undo step as the theme change (`rebakeIcons()`). Icons with literal colours and Fluent Color icons are unaffected.
- **Before save**: `doSave()` in `app/commands.ts` (behind **Save** and **Save as**) calls `rebakeIconsBeforeSave()`.
- **On open**: `openProject()` (`core/io/open.ts`) calls `pruneStaleIcons()`. A binding whose slot no longer holds what was baked (the picture was replaced in Power BI or by an image edit) is dropped and the image wins; a binding to a set in `REMOVED_ICON_SET_IDS` is dropped and its picture stays as a plain image. Both are reported as info diagnostics.
- **Resources**: a baked resource is deleted once nothing references it, and only items named `LumenIcon_` are ever deleted (`releaseIconResource()`).

On the canvas, the image visual draws the icon component inline (never the stored file content, so an annotation cannot inject markup) and the card draws its data URI with `<img>`.

## Lazy loading and readiness

`LOADERS` in `registry.ts` maps each set to a dynamic import:

```ts
const LOADERS: Record<IconSetId, SetLoader> = {
  lucide: { load: () => import('react-icons/lu'), prefix: 'Lu', kind: 'react-icons' },
  'fluent-color': { load: () => import('./sets/fluentColor.generated'), suffix: 'Color', kind: 'fluent' }
}
```

A set loads when the picker shows it, when a canvas visual draws one of its icons, and right after a report that uses it is opened (so re-bakes inside edits are synchronous). Loading a set also loads `react-dom/server`, which renders the picture copy. While a set loads, the app counts as busy (`app/readiness.ts`), so captures, the sweep and exports wait.

The two component kinds differ: react-icons components take `size`, `color` and `strokeWidth`; Fluent components are sized with `fontSize` (their root is `1em`) and need an `idPrefix` so that gradient and clip ids do not collide between copies. Every canvas and picker instance gets a `useId`-based prefix.

## Adding a set

The steps are in [ICONS.md: Adding a set](../ICONS.md#adding-a-set): an id in `IconSetId` / `ICON_SET_IDS`, metadata in `ICON_SETS`, a loader line in `LOADERS`, the licence text under `resources/licenses/icons/` and a row in `THIRD_PARTY_NOTICES.md`, then a review of the curated groups using the counts `registry.test.ts` prints.

## Considerations and limitations

- That Power BI Desktop displays an SVG registered resource in the image visual and an SVG data URI as the new card's image URL is assumed, not tested: there is no Power BI Desktop on Linux. Saved `visual.json` files with icons were validated against Microsoft's published visualContainer schema (see ICONS.md for the versions).
- Pictures were checked in Chromium only. Fluent pictures size their nested root with `font-size` and `1em`, which other SVG renderers may not support.
- Icons cannot be saved into a `.pbix`, because Lumen does not write `.pbix`; they are saved through PBIP or the `.wbi` bundle.
- Fluent marks its `*Color` components as deprecated in favour of a future colour API; they are still shipped.
- Button icons, shape fills, page backgrounds and conditional-formatting icons do not offer the picker yet; ICONS.md lists where it could plug in.
